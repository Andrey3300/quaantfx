# SYNTH·OTC

Демо-платформа бинарных опционов. Все котировки — синтетические (генерируются сервером), реальные деньги не используются.

## Текущий статус

- **Этап 1 — готов: бэкенд.** Авторизация с хешами паролей (bcrypt), серверный движок котировок + SSE, закрытие сделок на сервере, очереди депозитов/выводов/верификации для админа, промокоды, блокировка пользователей.
- **Этап 2 — готов: фронтенд подключён.** Одностраничник работает через API: рендер графика не менялся, заменён только слой данных (логин/регистрация, балансы, сделки, финансы, профиль, KYC-загрузка документов, промокод в форме депозита). Админка — страница `/admin`.
- Проверено смоук-тестами API и jsdom-сценариями интерфейса.
- **Этап 3 — дальше:** фронтовые баги из списка A, живое тестирование.

Полный список багов и переделок со статусами: [PLAN.md](PLAN.md)

## Запуск

```
cd server
npm install
npm start          # http://localhost:3000  (PORT=… npm start — другой порт)
```

Глубина истории — переменной `DEPTH` (дефолт `home`):

| `DEPTH` | где | S5 | H1 | RAM (все 82 актива) | билд актива |
|---------|-----|----|----|---------------------|-------------|
| `home`  | мощная машина (8700F/32ГБ) | ~сутки | ~год | ~1–1.2 ГБ | ~0.2 с |
| `lite`  | Vercel / слабый хостинг | ~2 ч | ~60 дней | ~десятки МБ | ~0.07 с |

```sh
DEPTH=lite npm start   # слабый хостинг: кольца как раньше (40–60 дней)
```

История строится лениво при первом запросе актива, так что реально память растёт
только за просмотренные активы (~13 МБ/актив в `home`). Дефолтная выдача не выросла:
первое окно — ~1600 свечей, глубже — чанки по скроллу влево.

## Админка (`/admin`)

Дашборд со счётчиками очередей · **Пользователи** (поиск, балансы, KYC-статусы, блок/разблок) · **Сделки** (все, фильтры) · **Депозиты** (зачислить с бонусом по промокоду / отклонить) · **Выводы** (выплатить / отклонить с возвратом) · **Верификация** (просмотр загруженных документов, подтвердить/отклонить с причиной) · **Промокоды** (создание кода с любым %, вкл/выкл, счётчик использований) · **Контакты** (email/telegram/телефон/компания/адрес/часы — показываются на странице условий) · **Команда** (только суперадмин: сотрудники с правами Нет/Смотреть/Делать по разделам, второй суперадмин, блок/удаление) · **Журнал** (кто/когда/что: сотрудники, блокировки, финансовые решения, кошельки, удаления) · **Чаты** (красная точка непрочитанных; правка ✏️ и удаление 🗑 только своих сообщений: у юзера — только новый текст / ничего, в админке оригинал и удалённые висят с красной плашкой; вложения до 5 файлов одним сообщением — JPG/PNG/GIF/WebP/SVG/PDF — с предпросмотром и подписью; быстрые ответы ⚡: закреплённая панель «Шаблоны» справа от чата (категории + шаблоны, кнопка «Использовать этот шаблон» вставляет текст+картинки без отправки, редактор шаблонов с прикреплением картинок); картинки открываются в лайтбоксе).

## Этап 3 (текущие правки)

- **KYC-мастер** как в Pocket Option: данные с подтверждением ✔ → страна → «Начнём верификацию» → тип документа (ID/паспорт/ВНЖ) → советы → загрузка: документ (до 2) + обязательное селфи с документом. У верифицированного кнопка загрузки скрыта; в админке виден тип документа и категории файлов (DOC/SELFIE).
- **Кошельки в админке:** раздел «Кошельки» — правка адресов по сетям + лог изменений (был/стал/кто/когда). Экран пополнения берёт адрес с сервера; QR убран.
- **Клиентские ID:** 8-значные последовательные (старт со случайного большого), показываются вместо внутренних id.
- **i18n:** ru/en/fr/de/pt/es/it/hi, переводится весь интерфейс и админка; переключатель — глобус на экране входа, пункт «Язык» в меню профиля и в админке; язык хранится per-user в localStorage, выбор гостя переносится в новый аккаунт.
- **Иконки активов:** круглые SVG-флаги пар и логотипы монет (локальный пак в `public/img/icons/`, перескачать — `node scripts/fetch-icons.mjs`).
- **График:** при панораме в историю окно заполняется свечами до правого края; бейджи значений индикаторов не наезжают друг на друга.
- **Гигиена:** `autocomplete=off` на формах входа/регистрации/профиля; резервированные имена (admin, moderator, support…) отклоняются сервером; выход/вход/регистрация делают полный reload — формы не текут между аккаунтами.

## Ключевые потоки

- **Депозит:** `POST /api/finance/deposits {method, amount, promo?}` → статус `pending` → админ `approve` → на реальный счёт падает `amount + бонус по промокоду`; `reject` → ничего не зачисляется.
- **Вывод:** `POST /api/finance/withdrawals` → сумма сразу резервируется → админ `approve` (выплачено) или `reject` (возврат на баланс).
- **Верификация (KYC):** мастер в профиле (данные ✔ → страна → тип дока → советы → файлы: документ ≤2 + селфи) → `POST /api/verify` (multipart: `doc_type`, `docs[≤2]`, `selfie`) → админ смотрит файлы с категориями и `approve`/`reject` с причиной.
- **Сделка:** `POST /api/trades {account, asset, dir, amount, expiry}` → сервер списывает сумму и фиксирует цену входа → по экспирации закрывает сам (вкладка пользователя может быть закрыта) и зачисляет выплату.
- **Промокоды:** админ `POST /api/admin/promos {code, bonus_pct}`; пользователь проверяет `GET /api/finance/promo/check?code=…`; бонус фиксируется в заявке и начисляется при апруве депозита. Коды многоразовые, пока не отключены (`/promos/:id/toggle`), счётчик использований ведётся.

## Котировки

- Тик каждые 500 мс, все активы; история свечей строится лениво при первом запросе актива (один раз).
- История отдаётся окнами: `GET /api/chart/:asset?tf=M1&before=<unix>&limit=1600` — без `before` свежее окно ~1600 свечей (+`hasMore`), с `before` — чанк старше (`hasMore`, `oldest`, `latest`). Скролл влево догружает чанки по 1000 с предзапасом (~900 свечей до края); лимиты клиента: ~6000 свечей на окно, 6 глубоких окон (LRU). Рендер графика не менялся.
- Живые цены: `GET /api/quotes?assets=EUR/USD OTC,Bitcoin OTC` — SSE, сэмпл каждые 500 мс.

## Условия и регистрация

- Страница условий — `/terms.html` (RU/EN-переключатель, контакты подтягиваются с `GET /api/contacts`).
- Контакты хранятся на сервере (плейсхолдеры `support@example.com` / `t.me/example_support` и т.п.), правятся в админке на вкладке «Контакты» (`GET/PUT /api/admin/contacts`).
- При регистрации обязателен чекбокс «Мне есть 18 лет, я принимаю [условия соглашения](/terms.html)»; сервер отклоняет регистрацию без `agree:true` (`400 agree_required`).

## Заметки по безопасности

- Пароли — только хеши (bcrypt), сессии — токены в БД (в куках только хэш не хранится, кука httpOnly).
- Заблокированный пользователь теряет все сессии сразу.
- Загрузка файлов: белый список mime, лимиты размера, имена файлов генерируются сервером.
- Для продакшена дополнительно: HTTPS, более жёсткий rate-limit, бэкапы `server/data/`.
